# C# VisionPro 模板匹配实战（齿轮检测 / 文字工具 / 彩转灰）

8.24 下午的课，康耐视 VisionPro 视觉软件的**模板匹配实战**。上午把模板匹配的基本操作过了一遍，下午拿真实案例上手：**齿轮数齿 → 文字工具动态显示 → 彩转灰**。

> 📌 这课是工业视觉（VisionPro 图形化拖拽工具），跟上完 C# 语法、WinForms 之后，就是往**机器视觉行业**走的一条线。核心思路（匹配独特特征、按结果分数调阈值）跟以后写视觉算法完全一脉相承。

## 🧩 复习上午：模板匹配基本操作

老师上午教的标准流程，下午全程都在用它：

1. 把图片切到 **TrainImage**
2. **抓取训练图像**
3. **框选模板**：框住目标的一部分（框一个齿 / 一个工件）
4. **中心圆点**（坐标轴）放到框的**正中心** —— 点「训练区域圆点的中心圆点」快速对齐
5. **训练**
6. **运行**，查看结果

## 🧩 案例 1：齿轮检测（数齿数）

素材：**齿轮检测**。三张图三种齿轮——**完整齿 / 缺一个齿 / 缺两个齿**。要检测的是**齿数**。

> 老师原话：不用视觉之前，齿数基本靠**人工点**，费时费力还容易出错；交给视觉技术，唰一下就出来。

### 参数三兄弟：旋转角 / 覆盖数 / 阈值

| 参数 | 作用 | 这课怎么调 |
|---|---|---|
| **旋转角（Rotation）** | 允许找任何角度的目标 | 设 **±180**，确保任意角度的齿都能找到 |
| **覆盖数（盖数 / 重叠数）** | 允许匹配到多少结果 | 齿多，设 **100 或 150**；但不能无限大——太大拖慢运行速度 |
| **阈值（预值 / 相似度）** | 低于这个分数不要 | 看结果分数定：**75 ~ 80** |

### 怎么排除"找过头"的结果

运行后可能会框出一大堆，**看结果的分数**判断：

- 前几个分数 9x% 都正常
- 往下看到 **87%**（8x7），选中看是不是真齿 → 是
- 一掉到 **6x%（比如 68.1）** 就开始不对了
- 结论：**要的结果是 87% 以上**，阈值设 75 或 80

⚠️ 调阈值的小细节：设 **75** 时还漏了个 **68 分的红框**，再往高调到 **80**，红框消失 → **最终 74 个结果**，没毛病。

### 结果就是齿数

模板匹配的 **结果数量（Count）就是齿数**：

- 完整齿轮 → **74** 个齿
- 缺一个齿 → **73** 个齿
- 缺两个齿 → **72** 个齿

切换图片一运行，数字跟着变，这就是检测效果。

## 🧩 案例 2：文字工具 CogGraphicLabel（在图上动态显示结果）

光找出结果还不够，要在**图片上用文字**直白展示出来。

### 工具藏在哪？

- 工具箱上排（罗鹿在外的）没有文字工具 → 在**下边的文件夹**里
- VisionPro 的很多工具作用相似，被**打包在文件夹**里
- 文字是"创建"出来的 → 找 **CREATION** 文件夹（创建的意思）
- 第 **3** 个工具，图标是个"文"字 → **CogCarrataGraphicLabel2**

> 💡 **Cog 前缀小知识**：Cog = 这家做软件的**公司名（康耐视 Cognex）的缩写**，相当于 LOGO。只要 **Cog 开头的工具就是 Cognex 公司的**。

### 使用步骤（第一步先把图像连上）

1. 把文字工具**拖进作业编辑器**
2. **连接图像**（左键按住拖转 / 右键连接）——不连图，文字没地方展示
3. 进入文字工具
4. **右边**：图片左上角有个 **Text**，鼠标放上去→**任意拖拽**调文字位置（放左边直观）
5. **左边**：设置**字形、字体大小、颜色** + 填**文本内容**，例如「齿轮的齿数：74个齿」
6. **运行**

### 关键：让数字动态变

问题来了：切换图片后，齿数变成 73 了，文字还写死"74"就不对。原因就是**文本内容是写死的**。

要动态变化，得把**模板匹配测出的数量**传给文字工具：

1. 模板匹配默认输出 **5 个**：Result、Translation X/Y（坐标）、Rotation（角度）、Score（分数）——**没有数量**
2. 右键模板匹配工具 → **添加终端** → 把 **Results 展开 → 找到 Count** → 添加输出
3. **Count 连到文字工具的 double** 输入（整数能被 double 表示，double 范围更大还能带小数）

### 花括号占位符（重点！）

光把数传进去，文字还是要让它"显示"出来：

1. 文字工具界面顶部有**选择器**，默认 `input graphic label text` → 改成最后一个 **formatted**（格式）
2. **formatted 里既能写文字，又能往文字里插入数值**
3. 插入方式：跟代码里的占位符一样，用**花括号**写 **大写 D** → `{D}`

文本这样写：

```
齿轮的齿数：{D}个齿
```

运行后 `{D}` 自动变成传进来的数字 → 切换图片：73 → 72 → 74，**动态显示**！

> 📌 为什么 `{D}`？D 代表 **double**，`{D}` 是它在文字里的**占位符**。想用整数就用 `{I}`（integer），因为 Count 本来就是整数，用 int 更搭。整数、小数都能装。

## 🧩 案例 3：弓箭案例（学会变通！）

上一课布置的案例：点**工件（弓箭）的数量**。一开始照老办法：

- 模板匹配框住**一整个工件** → 旋转角、覆盖数设好，反复调阈值
- 问题：整个工件**特征太多**，一歪、光线一暗，**误差就大**
- 阈值一路降到 **0.45 → 0.41 → 0.26**，有的图还是匹配不到
- ⚠️ **预值最低最低只能到 0.4**，再低顶多匹配到了，**误差也大到没法用**

### 变通思路：匹配独特特征

与其匹配一整个工件，不如匹配它的**独特特征**——中间的**轴孔**。

匹配中间轴孔的数量 = 匹配工件数量。思路一转变，还是那套参数，**阈值都不用怎么调（4期就搞定）**，效果又简洁又稳。

💡 **核心心得：模板匹配要挑目标身上"独特、变化小"的特征来当模板，别框一大片。**

## 🧩 案例 4：遥控器（彩转灰，为什么）

老师自己手机拍的照片（两个遥控器），要匹配出两个框。问题来了：

### 报错：「图像类型不受此操作的支持」

- 先排除**图片后缀名**：这张是 **jpg**，但传感器案例是 **bmp** 也一样报错 → 跟后缀名**没关系**
- 再看**图片内容格式**：之前所有能做案例的图都是**灰度图**（套环、弓箭全是 `Grey`）→ 这遥控器是 **RGB 彩色图**
- 结论：**模板匹配只支持灰度图，彩色图不能训练**

### 为什么只支持灰度图？

老师解释：VisionPro（这个软件）是 **2001 年**开发的，那会儿电脑还是大脑袋台式机，配置很一般。

- 彩色图**内存大**、处理慢
- 灰度图**不怎么吃配置**、单位时间检测得多
- 为了**更多用户（企业）带得动**，作者把最常用的工具（模板匹配等）**只设计成支持灰度图**

### 解决：彩转灰工具 CogImageConvert

- 工具箱 → 下面文件夹 → **IMAGE 文件夹** → 第 **5** 个工具 → **Image Convert（图片转换）**，图标**一半彩一半灰**
- 使用超简单：**拖进来 → 连接图片 → 进入 → 运行 → 搞定**
- 运行后图片导航栏有个**新图片**，就是**转灰后的灰度图**
- ⚠️ **重点：模板匹配连的图片，一定要连"转灰后"的那张**，不是原图

### 养成好习惯

> 以后**用模板匹配（或需要转灰的工具）之前，先检查图片是彩色还是灰度**。是彩色就先加个彩转灰工具。

## 🧠 一句话总结

1. **模板匹配三步走**：框典型特征 → 旋转角 ±180、覆盖数适量 → 按**结果分数**定阈值
2. **数一类东西**（齿、工件）：模板匹配的 **Count 结果 = 数量**，右键添加终端把 Count 导出来
3. **图上动态显示数字**：文字工具 CogGraphicLabel + **formatted** 选择器 + **`{D}` / `{I}` 花括号占位符**
4. **匹配不上别死磕**：换**独特特征**（轴孔）当模板，比框整个工件稳得多
5. **彩色图做不了模板匹配**：先拖 **Image Convert 彩转灰**，再连灰度图

## 📚 作业

1. 齿轮检测：完整齿 74 / 缺一齿 73 / 缺两齿 72，把齿数用文字工具**动态显示**出来
2. 弓箭案例：用**轴孔**做模板匹配工件数量，体会和框整件工件的差别
3. 遥控器案例：老师发的手机照片导入新项目，**先转灰**再用模板匹配，把两个遥控器都框出来
4. 练熟之后**拿自己手机拍周围物体**当素材（手机照片基本都是彩图，记得转灰）
