# C# 调试

调试就像**时间暂停机器**——把代码的运行速度降下来，一句一句看它怎么跑的，找出哪里出了问题。

## Debug 模式 vs Release 模式

VS 工具栏有个下拉框，选 Debug 还是 Release：

| 模式 | 说明 |
|---|---|
| **Debug** | 包含完整调试信息，**不做优化**，便于排查问题 |
| **Release** | 对代码进行优化（可能调整执行顺序或移除不影响结果的变量），会导致调试行为难以预测 |

> ⚠️ 养成好习惯：**调试时一定要用 Debug 模式**！Release 模式会乱改你的代码，报错了你都看不懂。

## 断点（Breakpoint）

断点是调试中用得**最频繁**的功能。

### 怎么用

点击代码行号左边的灰色区域（断点列），就会出现一个红点。

### 作用

程序运行到有断点的那一行就会**自动暂停**，等你下命令。

### 实际操作

```csharp
// 在任意行加断点，运行后会停在这一行
// 点「继续」就接着跑到下一个断点
// 再点继续就跑完了
```

### 去掉断点

再点一次红点就没了。

## 逐语句 / 逐过程 / 跳出

当程序在断点处停下来后，可以用这三个操作来控制它的运行：

| 操作 | 快捷键 | 作用 |
|---|---|---|
| **逐语句** | `F11` | **每一行每一行地运行**，会进入方法内部一行行执行 |
| **逐过程** | `F10` | **跳过整个方法**，直接把方法一口气运行完，不进去看 |
| **跳出** | `Shift+F11` | 把当前方法剩下的代码一口气全跑完，跳回到调用它的位置 |

### 配合使用的技巧

如果知道错误在 `Add` 方法里：
1. 先用 `F10` 跳过没问题的 `Method1`、`Method2`
2. 到 `Add` 方法时用 `F11` 一步一步看
3. 观察变量的变化，找出问题

## 监视窗口 & 局部变量

调试时下面会弹出两个窗口：

- **监视 / 局部变量**：显示当前所有变量的值和类型
- **错误列表**：显示编译错误

> 如果没有这些窗口，在 **视图** 菜单里找，或者在 **调试 → 窗口** 里调出来。

## 实战：排查数组越界

```csharp
static int Add(int[] nums)
{
    int result = 0;
    for (int i = 0; i <= nums.Length; i++)  // <= 应该是 <
    {
        result += nums[i];
    }
    return result;
}

// 调用
int[] arr = { 1, 2, 3 };
int sum = Add(arr);  // 会报索引超出界限
```

用断点 + `F11` 逐语句运行，就会发现：
- 第一次循环：`i=0`，加 `arr[0]` ✅
- 第二次循环：`i=1`，加 `arr[1]` ✅  
- 第三次循环：`i=2`，加 `arr[2]` ✅
- 第四次循环：`i=3`，`arr[3]` 不存在 ❌

**原因**：循环条件应该是 `i < nums.Length`，写成 `<=` 多了一次越界。

修复后就好了～
