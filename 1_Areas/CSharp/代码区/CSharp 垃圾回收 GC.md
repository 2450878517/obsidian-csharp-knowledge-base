# C# 垃圾回收（GC）

上一节讲了堆上的引用类型不会自动消失——谁管它？**垃圾回收（GC，Garbage Collector）**。它是 .NET 运行时自带的**自动内存管理机制**，专门负责回收那些没人再用的对象。

## 🧩 GC 是干嘛的

GC 专门负责：

1. **跟踪**堆上分配的所有对象
2. 找出**已经没有任何代码还在引用**的对象（= 垃圾对象）
3. **回收**它们占用的内存，腾出来给新对象用

**快递柜比喻**：你取完快递，快递柜那个格子的号码还占着。GC 看到你这个柜子号不用了，就把号码回收清空，下一个人来就能用这个格子了。

## ⚠️ 没有 GC 会怎样

以前 C 语言 / C++ 是要**手动释放内存**的，问题一堆：

- **忘记释放** → 内存越用越少，最后**内存泄漏**
- **释放错 / 提前释放** → 人家还在用，你给释放了，**程序直接崩溃**

GC 的出现就是让普通开发者从这种高风险操作里解脱出来——你不用管释放，它会自动判断哪些对象长时间没人用，然后清掉。

## 🧩 GC 怎么干活（原理）

GC 会周期性检查所有对象：正在使用的**打标记**，长时间没标记的（= 没人用了）就**清掉**。清完一轮再重新标记，反复循环，把不用的东西一点点清出去。

## ⚠️ GC 只管托管内存，不管非托管资源！

GC 管的是内存，但像**文件句柄、数据库连接、网络连接**这些**非托管资源**，GC 管不了——它只会「慢慢清」，可能来不及释放就堆一堆，造成内存泄漏。

所以这类资源**用完了必须手动立刻释放**。C# 提供的最简单方式就是 **using 语句**：

```csharp
using (StreamReader sr = new StreamReader("1.txt"))
{
    string all = sr.ReadToEnd();   // 读文件内容
    // 用完立刻释放，文件马上被关闭
}
```

`using` 会在代码块结束时**自动调用释放方法（Dispose）**，相当于自动写了 `sr.Dispose()`。文件读完立刻关掉，不留占用。

```csharp
using (var conn = new MySqlConnection("..."))
{
    // 用完数据库连接，自动释放
}
```

> ⚠️ 这里的 `using` 是「用完自动释放资源」，和代码顶上的 `using System;`（引用命名空间）**不是一个东西**，别搞混。

## 🧠 GC 知识总结

1. **GC 是自动的**——不用手动调用，它能精准判断对象还在不在用
2. **短命对象回收快**——用完就不用了，立马回收；**长命对象回收低频**——反复使用的对象回收得少
3. **非托管资源（文件/网络/数据库连接）必须及时释放**——用 `using` 语句最佳
4. **尽量别干扰 GC**——不要手动乱调 `GC.Collect()`、别滥用静态大对象，让 GC 自己管
