# C# 委托（delegate）

委托（delegate）是 C# 里一种**特殊的类型**，用来**安全地封装对方法的调用**。大白话讲：委托是一个**专门装方法的容器**，它可以让**方法当作参数来传递**。

## 为什么叫「委托」

现实生活里：自己没时间做、或者有特殊情况做不到的事，就会**委托别人帮忙干**——比如你人在北京旅游，郑州家里要盖章，你没法飞回去，只能委托别人去办。

代码里也一样：**有些方法你没办法直接调用**（被特殊情况挡住了），那就委托给一个「代理人」，让代理帮你去执行这个方法。

## 使用委托的步骤

1. **声明**委托（delegate）
2. **定义**委托
3. 委托内部**写逻辑**（把方法挂进去）
4. **调用**委托
5. **释放**委托

声明和定义经常可以合在一起写。

## 无参委托

```csharp
// ① 声明委托：delegate + 返回类型 + 委托名 + ()
delegate void WT();
```

```csharp
// ② 写一个方法
static void ADD()
{
    Console.WriteLine("ADD 方法跑起来了");
}
```

```csharp
// ③ 把方法挂到委托上，④ 调用
static void Main(string[] args)
{
    WT wt = ADD;   // 告诉委托：你要帮我干 ADD 这件事
    wt();          // 委托干活 → 输出 "ADD 方法跑起来了"
}
```

## 有参委托

无参委托**不能挂有参方法**——参数没地方放，会报错「没有匹配的重载」。

所以有参方法要用有参委托：

```csharp
delegate void WT2(int a);

static void ADD2(int a)
{
    Console.WriteLine(a + " 传进来啦");
}

WT2 wt2 = ADD2;
wt2(45);   // 调用时把参数传进去 → 输出 "45 传进来啦"
```

⚠️ 委托括号里的参数类型，要跟方法的参数类型**一致**——参数名字无所谓，**类型必须对上**。

## 有返回值的委托

方法有返回值，委托也得有对应的返回类型：

```csharp
delegate int WT3(string t);

static int ADD3(string t)
{
    Console.WriteLine(t);
    return 666;   // 返回 int
}

WT3 wt3 = ADD3;
int result = wt3("你好");   // 接收返回值
```

⚠️ 返回类型对不上，编译直接报错。

## 核心规律：委托结构 = 方法结构

委托要能挂上一个方法，**参数个数、参数类型、返回类型必须和方法一致**。委托就是照着方法「刻」出来的模子——模子不对，方法就放不进去。

## 一个委托干多件事（多播委托）

一个委托可以挂**多个方法**，一次调用全部执行。但符号要分清：

```csharp
// = 是赋值：挂上 ADD，之后再 = 会覆盖
WT wt = ADD;
wt = ADD2;   // 之前的 ADD 被顶掉了，现在只挂 ADD2
```

```csharp
// += 是追加：可以挂好几个
WT wt = null;
wt += ADD;    // 挂 ADD
wt += ADD2;   // 再挂 ADD2
wt += ADD3;   // 再挂 ADD3
wt();         // 一次调用，三个方法都跑起来
```

⚠️ **局部委托声明后必须初始化**（`= null` 或直接 `= 方法`），否则第一次 `+=` 会报错「使用了未赋值的局部变量」。在类里声明的委托会自动初始化成 null，不用手动。

## ⚠️ 委托为空的坑 & 问号调用

把挂上的方法都 `-=` 减光之后，委托里就空了。这时再调用 `wt()` 会崩：**未将对象引用设置到对象的实例**——你让代理人干活，却没说让他干哪件事。

两个防坑办法：

```csharp
// 方式一：调用前先判断
if (wt != null)
{
    wt();
}

// 方式二：问号点 Invoke（推荐，一行搞定）
wt?.Invoke();
```

`?.Invoke()` 的作用和 `if` 判断一模一样：委托里有内容就运行，没内容就不运行、不报错。**问号千万别漏**，漏了等于白写。

## 委托声明在哪都行

委托可以写在不同位置，调用方式不太一样：

- **方法内部**：局部委托，必须初始化
- **类中**：委托用**类名**去调用（static 风格）
- **命名空间中**：在类里实例化委托字段，通过**对象实例**调用

用哪种都行，看你方便。

## 同步 vs 异步：Invoke / BeginInvoke

- `Invoke()`：**同步**——等委托干完，程序才继续走
- `BeginInvoke()`：**异步**——委托自己去干，程序先往下走
- 面试爱问「`Invoke` 和 `BeginInvoke` 区别」——一个同步，一个异步
- 异步后面学到再深入；目前项目里 `BeginInvoke` / `EndInvoke` 基本用不上

## 🎬 案例：跨窗体传值（预告）

后续做窗体应用时，委托的典型用途是**跨窗体传值**：在窗口一里点一下按钮，某个数据就通过委托「传」到窗口二里——两个窗口之间的数据传递，靠的就是委托。

## 📚 作业

自己练习：定义一个无参委托，写三个结构相同、但输出不同逻辑的方法（比如 ADD / SUB / MUL），用 `+=` 把三个方法全挂到同一个委托上，一次调用让三个方法都跑起来。
