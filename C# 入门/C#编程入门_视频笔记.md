## 🛠️ 开发环境
- 使用 Visual Studio 作为开发工具，界面分为左右两半区域。
- 左半边：打开最近使用过的项目或文件；右半边：从存储库下载、打开本地项目、或创建新项目。
- 创建项目时筛选语言（C#）、平台（Windows）、项目类型（控制台应用）。
- .NET Framework（旧版，适合学习）与 .NET Core（新版，跨平台），本次使用旧版。
## 📝 注释
- 单行注释：使用 // 标注信息或临时禁用某行代码。
- 多行注释：使用 /* ... */ 包裹一段文字。注释不会被编译器执行。
## 🖨️ 输出语句
- Console.WriteLine()：输出内容后自动换行。
- Console.Write()：输出内容后不换行，光标停留在同一行末尾。
- 可以用输出语句拼接字符图案，例如构建旗子、圣诞树等。
## 📦 数据类型
- 值类型（存实际数据）：int、float/double、char、bool、decimal（高精度，金融计算用）。
- 引用类型（存地址引用）：string、class、数组、interface、delegate。
- 变量声明示例：int number1 = 10;
## 🔄 类型转换
- 隐式转换（自动）：小范围 → 大范围，无风险，如 int → double。
- 显式转换（手动）：大范围 → 小范围，需强制指定。
- 方式一：(目标类型) 如 (int)3.14 → 3（直接截断）。
- 方式二：Convert.ToInt32() 如 Convert.ToInt32(3.6) → 4（四舍五入）。
## 🔗 字符串拼接
- 使用 + 号直接连接："Hello" + " " + "World" 变 "Hello World"。
- 使用 $ 字符串插值（推荐）：$"结果是{变量名}"，比 + 拼接更清晰。
## 🧮 算术运算符
- 基础运算：加法（+）、减法（-）、乘法（*）。
- 除法（/）：整数除法得不到小数（如 6/5=1），需将操作数转为 float/double。
- 求余（%）：获取除法后的余数，常用于奇偶判断等场景。
- 自增自减（++ / --）：前置（++i）先自增再参与表达式；后置（i++）先参与表达式再自增。for 循环中通常用 i++，详见循环章节。
- 复合赋值（+=、-=、*=、/=）：如 a += 3 等价于 a = a + 3。
## ⌨️ 用户输入
- 使用 Console.ReadLine() 读取用户输入（返回字符串）。
- 使用 int.Parse() / double.Parse() / Convert.ToInt32() 将字符串转为数值类型。
- 示例：int age = int.Parse(Console.ReadLine());
## 📋 实践案例
- 求平均数：用户输入两个数字，计算并输出平均数。
- 计算每平米价格：输入房屋面积和总价，计算每平米单价。
- 计算 BMI 指数：输入体重和身高，计算 BMI 值。
## 🔀 分支语句（if / else if / switch）
- 分支语句根据条件执行不同操作，打破线性执行。包括 if、else if、switch。
## 📍 if / else 单分支
- 模板：if (条件) { 满足时执行 } else { 不满足时执行 }。
- 关系运算符：==（等于）、!=（不等于）、>、<、>=、<=。
- 注意：比较用双等号 ==，单等号 = 是赋值。
- 案例：if (age >= 18) 输出"可以进入"，else 输出"不可以进入"。
## 🌿 else if 多分支
- 模板：if (条件1) {...} → else if (条件2) {...} → else { 其他情况 }。
- 案例（公交优惠）：if (age <= 12 || age >= 50) → 免费，else → 支付 0.5 元。
## 🧠 逻辑运算符
- &&（与）：两个条件同时满足。
- ||（或）：任一条件满足即可。
- !（非）：取反。
## 📊 成绩评级案例
- 90-100 → A，70-89 → B，60-69 → C，0-60 → D。
- 防呆处理：输入 >100 或 <0，提示"输入的成绩不符合要求"。
## 🔘 switch 分支
- 适合精确值匹配（如菜单选择）。
- 模板：switch (变量) { case 值1: ... break; case 值2: ... break; default: ... break; }
- 每个 case 以 break 结束，default 可选但推荐使用。
## 💡 总结
- if 适用广泛，是通用选择；switch 在精确值匹配时更清晰。
- 三元运算符（条件 ? 值1 : 值2）可简化单分支判断，适用范围有限，了解即可。
- 注意防呆处理，避免输入异常值导致程序崩溃。
## 🔁 for 循环
- for 关键字用于创建循环结构，可重复执行代码多次。
- 模板：for (初始化; 判断条件; 迭代更新) { 循环体 }。
- 三个部分：初始化（int i = 0）、判断条件（i < 100）、迭代更新（i++）。
- i++ 和 ++i 在 for 迭代位置效果一样，但表达式中行为不同（详见运算符章节）。
## ⭐ 案例：星号矩阵
- 需求：输出 100 行 × 10 列的 * 号矩阵。
- 先用一行代码输出 10 个星号，再用 for 循环重复 100 次。
- 循环不仅能重复执行，还能生成有规律的内容。
- 拓展：利用循环生成从 1 到 100 的数字。
## 📌 数组基础
- 索引从 0 开始，通过 array[index] 访问和修改元素。
- array.Length 获取数组长度，遍历时避免硬编码。
## 🔄 遍历
- for 循环：通过索引遍历，适合需要索引位置的场景。
- foreach 循环：依次取出每个元素，更简洁，不需关心索引。
## 🔢 排序
- Array.Sort() 默认升序（从小到大）。
- Array.Sort() + Array.Reverse() = 降序（从大到小）。
## 🔍 元素查找
- Array.IndexOf()：查找元素第一次出现的索引，不存在返回 -1。
- Array.LastIndexOf()：查找元素最后一次出现的索引。
- Contains() / Any() / FirstOrDefault()：判断元素是否存在。
## 🗺️ 二维数组
- 声明：int[,] matrix = new int[行数, 列数]。
- 访问：matrix[行, 列]，嵌套循环遍历（外层行，内层列）。
## ⚠️ 易错点
- 索引越界会报 IndexOutOfRangeException。
- 索引从 0 开始，别和从 1 计数的习惯搞混。
- 未初始化的数组（null）不能直接使用。
## 🎬 7月24日上午 — 列表(List)
## 📋 列表的概念
- 列表和数组类似，都是存储同类型内容的集合
- 列表解决了数组大小固定、无法动态调整的问题
- 列表可以自动调整大小，支持增删改查操作
## 🆕 创建列表
- 方式一：先创建空列表，后续再添加元素
- 方式二：创建时直接加入初始元素
## ➕ 添加元素
- add() 方法：逐个追加元素
- insert() 方法：插入到指定位置
- addAll() 方法：将另一个集合的所有元素批量加入
## 🔍 访问与修改
通过索引访问元素（索引从 0 开始）
- 通过索引赋值修改元素
## 🗑️ 删除元素
- remove()：删除指定值（只删第一个匹配项）
- removeAt()：按索引删除
- removeAll()：删除所有匹配项（配合条件表达式）
- clear()：清空整个列表
## 🔄 遍历与排序
- 使用循环遍历列表
- count / length 获取列表大小
- Sort() 默认从小到大排序
- Reverse() 反转成从大到小
## 🔗 列表与数组互转
- 列表可以和数组互相转换，类型要保持一致
## ⚠️ ArrayList（非泛型集合）
- ArrayList 可以存放任何类型的对象
- 类型不安全，容易引发运行时错误，一般不推荐使用
- 装箱（Boxing）：值类型 → object 类型
- 拆箱（Unboxing）：object → 值类型
- string 是引用类型，行为类似值类型，但不涉及装箱拆箱
## 🎬 7月24日下午 — char类型与方法
## 🔤 char 类型
- char 表示单个字符，占用 2 个字节（16 位）
- 基于 Unicode 编码，范围 0~65535
- 前 256 个字符对应 ASCII 表
- 每个字符内部都有对应的数字（如 'A'=65，'7'=55）
- 定义时必须用单引号：char c = 'A';（不能用双引号）
- char.ToUpper() / char.ToLower() 做大小写转换
## 🏗️ 方法（Method）
- 方法将一段完成特定功能的代码打包，方便重复使用
- 方法通常写在 class 内部（Program 类或自定义类）
- 定义方法需要：访问修饰符、返回值类型、方法名、参数列表、方法体
- 无返回值用 void，有返回值用 return
## 📥 方法的参数与调用
- 方法可以通过参数接收外部传入的数据
- 调用时参数数量和类型必须与方法定义一致
- 例如加法方法：接收两个 int 参数，返回 int 结果
- 方法可以避免重复代码，提高复用性和可维护性
## 📦 char 数组与 Substring
- char[] arr = "Hello".ToCharArray(); 将字符串拆成字符数组
- Substring(起始索引, 长度) 提取部分字符
### 字符串操作
- 字符串可以做的事：字符计数、遍历每一个字
- 用 ToCharArray() 把字符串拆成单个字符放到数组里
- 拆分后可以用索引访问或 foreach 遍历每个字符
### 凯撒加密（Caesar Cipher）
- 加密规则：每个字母的 ASCII 编码 +3
- 解密规则：每个字母的 ASCII 编码 -3
- 边界处理：X/Y/Z 加3超出范围就减26绕回开头，大小写分开处理
- 解密流程：ToCharArray() → 遍历 → 编码-3 → 边界判断 → 转回字符 → 拼回字符串
### 方法封装
- 把 BMI 计算或加密解密的代码包装成方法
- 定义参数（传入数据）和返回值（传回结果）
- 好处：代码简洁、可复用、好维护
### 使用类封装方法
- 把方法手动封装到创建的类中（如创建 Math 类放加法）
- 方法模板：返回类型、方法名、参数列表、方法体
### 访问修饰符
- public — 公开的，谁都能用
- private — 私有的，只有类内部能用（默认）
- internal — 当前程序集内可用
### 方法重载（Overload）
- 同⼀个类中定义多个同名方法，参数列表不同
- 返回类型必须相同，举例：Add() 支持2个或3个参数
### static 关键字
- 加上 static 后成员属于类本身，无需实例化即可通过类名调用
- 所有实例共享同一个静态成员
### params 关键字
- 允许方法接受可变数量的参数
- 简化传入数组的麻烦（如求和时可传入任意多个数字）
## 🔧 ref 和 out 关键字
- ref 让方法直接操作原始变量，修改会反映到原数据上，像是改原件而不是复印件
- out 用于输出：传入没有初始值的空变量，方法内部赋值并传出，同样修改原始变量
- 不带关键字时，方法默认复制一份数据运算，不会改变原始变量
- 应用场景：交换方法、需要方法返回多个值时
## 🎲 Random 随机数生成
- 用 Random 类生成随机数
- 通过设定区间（左闭右开）控制范围：如 1 到 7 模拟 1 到 6 的骰子
- 用 1 到 100 的随机区间模拟百分之几的中奖概率
- 应用场景：游戏概率逻辑、抽奖模拟等
## 📋 枚举（enum）
- 用枚举代替纯整数，让代码更具可读性和类型安全
- 如用 Week 枚举表示周一到周日，成员默认从0开始递增
- 可手动指定整数值，能通过底层整数进行转换和访问
- 只能使用定义范围内的值，否则会返回错误
## 🏗️ 结构体（struct）vs 类（class）
- 结构体是值类型，赋值时复制整个数据，修改一个变量不影响另一个
- 类是引用类型，赋值传递地址，修改会互相影响
- 需要数据独立性时（如复制学生信息）应使用结构体
## 🔒 属性（Property）
- 通过 get 和 set 访问器控制字段的读写
- 可在 set 中加入限制条件，如年龄必须大于0，防止非法数据
## 🧩 面向对象四大特征
- 封装 — 提高数据安全、方便维护、降低复杂度、增强复用性
- 继承
- 多态
- 抽象
## 🐛 7月29日上午 — 调试 & 构造函数
### 调试 (Debug)
- 调试就像时间暂停机器，让代码一句一句运行，观察数据变化
- **Debug 模式**：包含完整调试信息，不做优化，方便排查问题
- **Release 模式**：代码优化，可能调整执行顺序，调试行为难预测
- **断点**：在行号旁点击设置，运行到该行会自动暂停
- **逐语句 (F11)**：一行一行执行，会进入方法内部
- **逐过程 (F10)**：跳过整个方法，不进去看内部
- **跳出 (Shift+F11)**：把当前方法剩下的代码一口气跑完
- **局部变量窗口**：显示当前所有变量的值，帮助定位问题
- **实战**：用断点 + F11 排查数组越界（`<=` 写成 `<` 导致多循环一次）
### 🔧 构造函数
- 特殊方法，在 `new` 对象时**自动执行一次**，初始化对象到可用状态
- **四大特征**：名同类名、无返回类型、自动执行一次、每类至少一个
- **优势**：自动执行（不会忘）、只运行一次（不会乱调）、继承友好（先父后子）
- **重载**：可以写多个参数不同的构造函数，`new` 时自动匹配
- **飞机案例**：无参（普通飞机）→ 有参（指定轮胎数）→ 多参（轮胎数 + 代级）
## 🎬 7月29日下午 — 静态构造函数 & 继承 & this & 异常处理
### 🏗️ 静态构造函数
- `static 类名()`，**没有访问修饰符**，不能有参数
- **只在类第一次被使用时运行一次**，之后再也不运行
- 应用场景：加载配置文件、游戏第一次加载资源
### 🧬 子类构造函数（继承）
- **先造祖线，再造自己**：创建子类时，父类构造函数先执行，子类后执行
- 把共有逻辑写到基类，子类用 `:` 继承，避免代码重复
- 示例：`Brain` 基类 → `Person` 和 `Cat` 继承，共享思考和记忆
### 🔗 base 关键字
- 父类构造函数有参数时，子类用 `base(参数)` 传参
- 父类构造函数重载时，`base` 自动匹配对应参数版本
### 👉 this 关键字
- **作用一**：`this.字段 = 参数`，区分同名的字段和参数
- **作用二**：`this(参数)` 在一个构造函数中调用另一个构造函数（构造函数链）
- 示例：`Car(string Brand) : this(Brand, 4)` 用户只输品牌时默认 4 轮
### 🛡️ try-catch 异常处理
- `try` 里放**可能爆错的代码**，`catch` 里放**出错后怎么办**
- 爆错不会让程序崩溃，而是跳到 `catch` 执行
- 适合处理用户输入不合法等情况（如输入 ABC 而不是数字）

## 🎬 7月30日上午 — 异常处理进阶 & var & 值类型引用类型
### 🧩 异常处理进阶
- try-catch 兜住错误不崩；`catch (Exception ex)` 里 `ex.Message` 看错误原因
- **Exception 是所有异常的老大**，子类按种类各抓各的：FormatException（格式不对）/ OverflowException（数字溢出）/ NullReferenceException（用了没实例化的对象）/ IndexOutOfRangeException（索引越界）/ FileNotFoundException（文件找不到）
- **多个 catch** 按错误类型分开处理，像分岔路口；不想细分就 `catch (Exception ex)` 一把抓
- `ex.StackTrace` 方法调用链（调试用）、`ex.InnerException` 内部异常（异常套异常）
- **finally**：不管 try 成败一定执行一次，用于关文件/释放资源（临时工离职前收拾工位）
- **throw**：手动报错 `throw new Exception("原因")`，可以指定异常类型
### 🧩 var 隐式类型
- 不知道类型时用 `var`，编译器根据右边的值**自动推断**；var 不是无类型，编译后和写具体类型一样
- 三条规则：只能**方法内部**用 / **必须立即赋值** / 初始值**不能 null**
- **匿名类型**：`var stu = new { name = "张三", age = 24 }` 临时对象，只能用 var 保存
- 不推荐滥用（代码是给人看的），工业相机等外部库类型太长才用
### 🧩 值类型与引用类型（栈和堆）
- **栈 stack**：值类型（int/bool/char/结构体），存值本身，快、小、方法用完自动清，像便利贴/前台吧台
- **堆 heap**：引用类型（string/数组/类/List），内容存堆、**地址存栈**，不自动清要等**垃圾回收 GC**，像后台大仓库
- 类 = 引用类型（共享），结构体 = 值类型（复制）——之前类 vs 结构体的根子就在这
- **装箱拆箱**：值类型包进 `object`（装箱），从 `object` 拆出来（拆箱）
- 静态区（加载堆）：类型信息、static 字段、字符串常量
- 📄 详细笔记见 [[C# 异常处理进阶]] | [[C# var 隐式类型]] | [[C# 值类型与引用类型]]

## 🎬 7月30日下午 — 垃圾回收 & 虚方法重写 & 抽象方法
### 🧩 垃圾回收 GC
- .NET 运行时自动内存管理机制：跟踪堆上对象，回收没人再用的垃圾对象、腾内存
- 快递柜比喻：取完货，柜号回收给下一个人用
- 没有 GC 得手动释放（C++），忘记→内存泄漏，释放错/提前→程序崩溃
- 标记机制：还在用的打标记，长期没标记的清掉，反复循环
- ⚠️ **GC 不管非托管资源**（文件/数据库连接/网络）→ 用 **using 语句**用完自动释放（隐式调用 Dispose）
- 总结：自动 / 短命对象回收快、长命回收低频 / 非托管用 using / 别乱干扰 GC
### 🧩 虚方法 virtual + 重写 override
- 普通方法子类只能继承不能改；父类方法加 `virtual`，子类同名方法加 `override` 就能改实现 → **多态**
- 动物案例：Animal.Shout() 加 virtual，猫「喵」狗「汪」，同一个命令不同行为
- 重写规则：方法名/参数/返回值必须和父类**一致**，只能改方法体（签名不能改，改了报「没有找到合适的方法来重写」）
- 带参数的虚方法：子类重写参数也必须一样
- **重载 vs 重写**（面试题）：重载=同类同名不同参数/编译时定；重写=子类继承父类同签名/运行时多态
- 重写可**连续**：孙子类能再重写子类；不想让后代重写 → override 前加 **sealed** 密封
- 使用注意：非必要不用虚方法 / 慎重改签名 / 强制子类改实现用抽象方法 / 防后代继续改写用 sealed
### 🧩 抽象方法 abstract
- 抽象方法 = **没有方法体的虚方法**，子类必须重写（不重写不让你用）
- 虚方法有默认实现、可不用重写；抽象方法强制子类重写
- 类里有抽象方法 → 类也必须加 `abstract`（抽象类）
- 父类给不出合理默认实现时用抽象方法
- 📄 详细笔记见 [[C# 垃圾回收 GC]] | [[C# 虚方法 virtual 与 重写 override]] | [[C# 抽象方法 abstract]]

## 🎬 7月31日上午 — 抽象类与接口
### 🧩 抽象类（abstract）
- 在抽象方法的基础上，类前加 `abstract` 关键字就变成抽象类
- 抽象类不能直接创建对象，只能作为其他类的模板或基类
- 抽象类为所有派生类定义框架
- 抽象方法没有方法体，必须由子类去实现
### ⚔️ 英雄职业案例
- 原本普通的基类可以直接实例化并调用普通攻击方法
- 把类和方法改为抽象后，就无法再直接创建对象了
- 抽象类中的普通方法也不能直接被调用：只能通过子类间接调用，或者把方法设为 static 后用类名直接调用
### 🗄️ 字段 vs 属性
- 字段：private 修饰的成员变量，只能在本类内部使用
- 属性：通过 getter/setter 与外界交互，外部可以通过属性来读取或修改字段
- 二者的共同作用：保护数据的安全性
### 🏷️ 接口（interface）
- 用 `interface` 关键字定义，只声明可以做什么，不提供具体的实现方式
- 命名规范：推荐以 `I` 开头
- 接口中的方法类似抽象方法，实现接口的类必须实现接口中的所有方法
- 一个类可以实现多个接口，这比只能继承一个抽象类更灵活
### 🧬 接口的继承
- 多个小接口可以组合成一个更大的接口
- 例：将「会爬行」和「会游泳」组合成两栖动物接口，还能在此基础上添加潜水等新技能
- 通过两栖动物的代码演示了接口从定义、继承到实现和调用的完整过程
### 🎽 接口的作用：资格证明
- 奥运会案例：普通人有跑步方法但缺少运动员接口，就无法参加奥运会
- 实现了运动员接口的对象，才能被传入奥运会方法中
- 接口可以用作权限限制：管理系统中只有具备管理员接口的人才能执行管理操作
### ⚖️ 抽象类 vs 接口
- 抽象类 ≈ 半成品的模板模具
- 接口 ≈ 一张技能契约

### 🎲 随机数重复问题
- 问题：连续 `new Random()` 得到的值相同
- 原因：循环速度太快，Random 基于时间做种子，同一时刻创建导致种子重复

### 🔀 接口方法冲突
- 问题：两个接口有相同签名的方法，一个类需要同时实现
- 解决：用显式接口实现（`I1.Method()` / `I2.Method()`）分别实现两个接口
- 调用时：必须通过对应的接口引用来调用
### 🧬 虚方法与重写
- `override` 重写：子类方法通过基类引用调用时表现出多态行为
- `new` 隐藏：用 `new` 关键字则不会多态，基类引用调用时走的是基类版本
### ⚙️ 字段初始化编译陷阱
- 问题：在另一个实例字段的初始化器里引用实例字段，会编译失败
- 原因：实例字段的初始化执行顺序不确定
- 解决：改用 `static` 字段，或把逻辑移到方法 / 构造函数里
### 📚 枚举替代魔法数字
- 用枚举（enum）替代性别、颜色这类魔法数字
- 相比硬编码数字：类型安全、可读性更好

## 🎬 8月3日下午 — 属性、字段与方法
### 🗄️ 字段 vs 属性
- 字段：存储数据的成员变量
- 属性：通过 getter/setter 控制字段的读写
- 案例：银行卡余额——用字段存数据，用属性控制谁能读、谁能改
### 🔒 属性的完整写法
- get 访问器：读取时执行，可返回字段值或加工后的值
- set 访问器：赋值时执行，可加入校验
- 案例：年龄属性——set 里判断必须大于 0，非法值直接拦截
- 只读属性：只写 get 不写 set
### 🛡️ 访问修饰符
- public — 谁都能访问
- private — 只有类内部能访问
- protected — 本类 + 子类能访问
- internal — 同一程序集内能访问
### ⚡ 静态属性与静态字段
- static 成员属于类本身，不依赖对象，用类名直接调用
- 所有实例共享同一个静态成员
### 📦 方法的定义与参数
- 方法封装逻辑代码，模板：访问修饰符 + 返回类型 + 方法名 + 参数列表 + 方法体
- 必选参数：调用时不能省略
- 可选参数：有默认值，调用时可以省略
- ref：直接操作原变量（改原件）
- out：用于输出，方法内部赋值传出
- params：接受可变数量的参数
### 🧬 方法重载与递归
- 重载：同名方法参数列表不同，调用时自动匹配
- 案例：Add() 支持 2 个或 3 个参数
- 递归：方法自己调用自己，需有终止条件
- 风险：没有终止条件会无限递归，栈溢出（StackOverflowException）
### ⚖️ 实例成员 vs 静态成员
- 实例成员：每个对象一份，通过对象访问
- 静态成员：类共享一份，通过类名访问
- 内存分配与调用方式不同

## 🎬 8月5日上午 — 泛型（Generic）
### 🧩 泛型引入：交换方法
- 交换两个 int 用临时变量 + `ref`：`Swap(ref int a, ref int b)`
- **默认传参只是复制副本，加 `ref` 才能真正修改外部变量**
- 想交换 double / string 等，每种类型都要重写一个方法 → **代码冗余**
### 🧩 泛型的概念
- 一种编写**类型无关代码**的技术：先写模板，不指定类型，使用时编译器自动生成对应类型版本
- 作用：一个方法适用所有类型；编译时检查类型；没有装箱拆箱、类型安全、不损失性能
### 🧩 泛型方法
- 方法名后加 `<T>` 尖括号，`T` 是类型占位符：`public static void Swap<T>(ref T a, ref T b)`
- T 的类型取决于调用时传入的类型（int / double / string 都能换）
### 🧩 泛型类
- 整个类都要处理多种类型时，泛型定义在类上：`class Box<T>`，字段 / 方法 / 属性全用 T
- 实例化必须指定类型：`Box<int> box = new Box<int>();`
- **只在方法内用 → 泛型方法；字段 / 属性 / 多方法都要用 → 泛型类**
### 🧩 泛型 vs Object（装箱拆箱）
- object 也能存任意类型，但值类型 ↔ object 涉及**装箱拆箱**：强制转换可能丢数据、影响性能
- 泛型没有装箱拆箱，类型安全、性能更好
### 📦 案例：能存任意类型的小盒子
- `Box<T>`：`void Set(T value)` 存入字段 + `T Get()` 返回字段
- `Box<int>` 存 99、`Box<string>` 存 "你好"，同一个类换类型就能用
### 📋 List<T> 就是泛型类
- `List<string>` 只能装 string，`List<int>` 只能装 int —— 底层就是泛型类封装增删改查
- 手动实现列表，也会用泛型类来做
- 📄 详细笔记见 [[C# 泛型]]

## 🎬 8月5日下午 — 字典（Dictionary）
### 🧩 为什么学字典
- 数组/列表存同类型数据，但**海量数据里找一条很难**——要么记位置，要么整条遍历
- 字典通过「**键**」快速定位，像现实字典查拼音，不用一页页翻
### 🧩 字典是啥
- 泛型集合类，存「**键值对**」：每一个值都有对应的键
- 创建：`Dictionary<键类型, 值类型> dict = new Dictionary<键类型, 值类型>();`
- 键类型、值类型按实际需求自己设（如 学号→姓名）
### 🧩 三个特点
- **键唯一、不重复**（像身份证号，不能有两个一样的）
- **通过键来找值**
- **键值绑定**——顺序怎么变，一个键永远对应那个值
### 🧩 增删改查
- 添加：`Add()`（键重复会**报错**）
- 修改：下标赋值 `dict[key] = 值`（键存在就**覆盖**，不报错）
- 删除：`Remove()`
- 查找：`dict[key]`（键不存在会报错 → 用 **try-catch** 防崩）
- 判断：`ContainsKey(键)` / `ContainsValue(值)`，有 true 无 false
### 🧩 遍历
- `foreach` + **键值对** `KeyValuePair<键类型, 值类型> kvp`，取 `kvp.Key` / `kvp.Value`
- 一个字典就是一堆键值对组成的
### 🧩 排序
- 字典没有 Sort()，用 `OrderBy`（升序）/ `OrderByDescending`（降序）
- 要填一个方法告诉它：**按键排还是按值排**（固定搭配）
### 🍎 案例：水果计数
- 水果名当**键**、数量当**值**；遍历时判断——没有就新增（值=1），有就值+1
### 📝 升级案例 & 作业
- 统计一段文字每个字的出现频率（字符串 `ToCharArray()` 拆字，再套水果案例）
- 作业：用字典统计《木兰诗》每个字的出现频率
- 📄 详细笔记见 [[C# 字典 Dictionary]]

## 🎬 8月6日上午 — 委托（delegate）
### 🧩 委托是什么
- 一种**特殊类型**，用来**安全地封装对方法的调用**；大白话：装方法的容器，方法可以当参数传递
- 现实类比：自己没时间/做不到的事委托别人干；代码里「无法直接调用的方法」让委托去跑
### 🧩 使用委托的步骤
- ① 声明委托 ② 定义委托 ③ 写逻辑（挂方法）④ 调用委托 ⑤ 释放委托（前两步常合并）
### 🧩 三种常见委托
- **无参**：`delegate void WT();` + `WT wt = 方法;` + `wt();`
- **有参**：委托括号里的参数类型必须和方法的参数一致（名字无所谓）
- **有返回值**：返回类型也要和方法一致，可接收返回值
- **核心规律：委托结构 = 方法结构**（参数个数/类型/返回类型都要对上）
### 🧩 多播委托（一个委托干多件事）
- `=` 是赋值会**覆盖**；`+=` 是**追加**，可挂多个方法，一次调用全跑
- 局部委托必须初始化（`= null` 或 `= 方法`），否则第一次 `+=` 报「未赋值的局部变量」
### 🧩 委托为空的坑
- 方法全 `-=` 减光后调用会崩（未将对象引用设置到对象实例）
- 防坑：`if (wt != null)` 或 **`wt?.Invoke()`**（问号别漏）
### 🧩 委托声明位置
- 方法内（局部，必须初始化）/ 类中（类名调用）/ 命名空间中（实例调用）
### 🧩 同步 vs 异步
- `Invoke()` 同步 / `BeginInvoke()` 异步；面试爱问区别，异步后面再学
### 🎬 预告：跨窗体传值
- 窗体应用里委托的典型用途：窗口一的数据通过委托传到窗口二
- 📄 详细笔记见 [[C# 委托]]

## 🎬 8月6日下午 — 委托进阶（Action / Func 与 Lambda）
### 🧩 为什么简化
- 每次用 delegate 都要先声明、写参数和返回值，太麻烦 → C# 内置 **Action / Func** 现成委托
### 🧩 Action / Func
- **`Action`**：装**无返回值**的方法；`Action<string, int>` 尖括号里写参数类型
- **`Func`**：装**有返回值**的方法；**最后一个类型是返回值，前面全是参数**（`Func<int,int,int>` = 两个 int 参数返回 int）
### 🧩 匿名函数
- 只用一次的方法不用单独封装：`Action wt = delegate() { ... };`，有参数写在括号里
### 🧩 Lambda 表达式
- 匿名函数再简化：去掉 delegate，参数 + 箭头 `=>` 指向逻辑
- 无参：`() => ...`；单参可省括号 `t => ...`；多参带括号 `(a, b) => ...`；参数类型可省（编译器推断）
- **表达式 Lambda**：单条逻辑可省花括号和 return：`(a, b) => a + b`
### 🧩 数组里的 Lambda（回顾）
- `Array.Exists(fruits, x => x == "西瓜")` 第二个参数就是判断委托；看不懂就还原成方法
### ⚠️ ?.Invoke() 的坑
- 委托有 int 返回值时 `?.Invoke()` 返回 null → int 不能为 null 报错
- 解决：`?? 0` 兜底默认值，或保证委托非空直接 Invoke
- 📄 详细笔记见 [[C# 委托进阶]]

## 🎬 8月7日下午 — 事件（Event）
### 🎬 案例：电视台 + 路人（委托版）
- 电视台类（发布新闻 SayNews）+ 路人类（接收信息），三个路人订阅
- 普通做法：SayNews 里手动调用每个路人 → 加/减路人都要改电视台类
- 委托做法：委托放命名空间，Main 里 `+=` 订阅、`-=` 退订，SayNews 触发委托；电视台类不用动
### ⚠️ 用委托的两个漏洞
- 漏洞一：委托能被任何人直接调用（`wt("假新闻")`），绕过电视台
- 漏洞二：`=` 赋值会覆盖掉之前所有订阅者，直接清空
### 🧩 事件（event）
- **事件**：语言级机制，用于「当某件事发生时通知其他对象的行为」
- 用法：委托声明前加 `event` 关键字
- 作用：① 只能 `+=`/`-=`，不能 `=`（防覆盖）② 只能通过封装方法触发，外部不能直接调
- 报错提示：「事件只能出现在 += 或 -= 的左边」
- 生活比喻：闹钟——闹钟响了才起床，别人随便喊不动
### 🧠 委托知识总结（三节课串）
- 无法手动调用方法 → 用委托；写法麻烦 → Action/Func；只用一次 → 匿名函数 → Lambda
- 用委托实现「通知其他对象」时有漏洞 → 用 **event** 保护（事件 = 上了锁的委托）
- 📄 详细笔记见 [[C# 事件]]

## 🎬 8月10日上午 — Equals 与 GetHashCode
### 🧩 判断相等 `==`
- 值类型（int、string）比较**内容**，一样就 True
- 类（引用类型）比较**地址** → 内容一样但地址不同也 False（两个 new 的对象永不相等）
- string 是引用类型但行为像值类型，会比较内容
### 🧩 `Equals` 方法
- object 自带的方法，任何变量都能 `.Equals()`，默认结果和 `==` 一模一样
- 区别：`==` 是**运算符**（逻辑写死），`Equals` 是**方法**（能被重写）
- 想比类的内容而不是地址 → 重写 Equals
### 🧩 重写 Equals
- 写在类里：`public override bool Equals(object obj)`（参数类型 object 是固定签名）
- 第一步 `obj is Person p` 判断是不是同类，不是就 false；第二步比内容（名字、年龄）
- 类里有 100 个字段也只在方法里写一次比较
### ⚠️ 重写 Equals 必须重写 GetHashCode
- 固定规律：两个对象 Equals 相等 → GetHashCode 必须返回相同值
- 配套写法：`public override int GetHashCode() { return Name.GetHashCode(); }`
- 不写编译器会警告，这是底层规律的硬性要求
### 🧠 一句话
- `==` 运算符写死，`Equals` 方法能重写；比内容用 Equals，别忘带 GetHashCode
- 面试爱问，实际开发基本用不到，了解即可
- 📄 详细笔记见 [[C# Equals 和 GetHashCode]]

### 🧩 JSON 与 XML
- **JSON** 是数据格式：对象最外层花括号 `{}`、数组最外层方括号 `[]`；C# 面向对象所以花括号用得多
- **JSON vs XML**：JSON 体积小 / 传输快 / 处理方便 / 直观；XML 是 90 年代的标签对格式，老项目历史数据还在用；**新项目用 JSON、老项目用 XML**

- 💼 面试题「存文件用什么技术」→ 答**序列化技术**（有工具包直接调用）

- 序列化前用 `if (a=="" || b=="")` 判断防存空数据

- ⚠️ **三个坑**：泛型 `<类型>` 必须写（as / 强转 / Convert 都不行）；顺序正好相反（文件→JSON→对象）；数据多个用 `List<Person>` 接收再遍历

## 🎬 8月14日上午 — 登录系统进阶（注册与 JSON 多对象存储）
### 🧩 昨天的坑：多对象怎么存
- 之前用 `AppendText` 追加保存 → 文件里是一堆**独立花括号**（各自独立对象）→ 读不了
- 正确做法：所有对象装进**一个 List**，序列化整个列表 → 文件最外层变成**方括号 `[]`**，能整体读回
### 🧩 追加 = 先读旧 + 加新 + 一起存
- `WriteAllText` 裸用是**覆盖写**，会把以前的数据全冲掉
- 要追加：先 `File.Exists` 判断文件在不在 → 在就读旧数据反序列化到列表 → `Add` 新对象 → 整个列表（旧+新）序列化写回 → 形成**累加**效果
- 多对象反序列化：`File.ReadAllText` + `DeserializeObject<List<类型>>` + foreach 遍历
### 🧩 综合实战：带注册的登录系统
- **注册 = 序列化**（账号存进 `user.json`），**登录 = 反序列化**（读文件查账号）
- User 类两个字段：UserName / Password；密码框 `PasswordChar='*'` + CheckBox 显示密码（沿用 [[C# 登录系统（窗体跳转与密码隐藏）]]）
- 校验一：账号密码**不能为空**：`if (textBox1.Text == "" || textBox2.Text == "")`（用 `||`）
- 校验二：账号**不能重复**：foreach 遍历旧列表，找到相同账号 → 「该账号已注册」+ return
- 登录逻辑：foreach 找账号 → 密码对就「登录成功」、错就清空重输
- ⚠️ **大坑（老师现场演示）**：「该账号不存在」必须放 **foreach 循环外面**——写进循环里，遇到第一个不匹配的账号就误报，哪怕账号明明在后面
